## Tier 1 — Quick Wins
*Small effort (S–M), immediate value. Build these first.*

---

### 1. Item Priority / Ranked Wants
Let owners mark items **Must Have / Would Love / Nice to Have**. Givers sort by priority. No more guessing what matters most.

- Add `priority TEXT CHECK IN ('high','medium','low') DEFAULT 'medium'` to `items` table
- Add `priority?: 'high' | 'medium' | 'low'` to `GiftItem` in `src/types/models.ts`
- Update `mapRowToItem()` in `ListService.ts`
- Add sort toggle on `ListDetailScreen.tsx` and colored left-border indicator on `GiftItemRow.tsx`

---

### 2. Soft Claim vs. Hard Claim
**Soft:** "I'm thinking about it" — yellow warning to others, not locked. **Hard:** locked. Prevents two people buying the same thing when one was still deciding.

- Add `claim_type TEXT CHECK IN ('soft','hard') DEFAULT 'hard'` to `claims` table
- Add `claimType?: 'soft' | 'hard'` to `ItemClaim` in `src/types/models.ts`
- Update `ClaimService.claimItem()` to accept `claimType` param
- `GiftItemRow.tsx` and `ItemDetailModal.tsx`: yellow badge for soft, green lock for hard

---

### 3. Giver Notes on Items
Owner attaches private notes to items revealed only *after* someone claims — e.g. "She already has the blue one, get red."

- Add `giver_note TEXT NULL` to `items` table
- Add `giverNote?: string` to `GiftItem` in `src/types/models.ts`
- Update `ListService.addItem()` / `updateItem()` to pass `giver_note`
- `AddItemScreen.tsx`: "Note for giver (hidden until claimed)" input field
- `ItemDetailModal.tsx`: show `giverNote` only when `isClaimedByMe === true`

---

### 4. Surprise Mode Toggle
Per-list setting where the owner sees only the price range and category of claimed items — not which item or who claimed it. The giver's identity stays hidden; the owner just knows something is coming.

- Add `surprise_mode BOOLEAN DEFAULT false` to `lists` table
- Add `surpriseMode?: boolean` to `GiftList` in `src/types/models.ts`
- Update `ListService.updateList()` to pass `surprise_mode`
- `ListDetailScreen.tsx`: when `isOwner && list.surpriseMode`, render claimed items as "A gift in the $X–$Y range" instead of item name
- Toggle in `ListEditScreen.tsx`

---

### 5. "In My Cart" / Delivery Stage
Givers can advance a claim through stages: **Claimed → Ordered → Delivered**. Other givers see the stage (prevents double-ordering); the list owner only sees "delivered" as a vague notification.

- Add `delivery_stage TEXT CHECK IN ('claimed','ordered','delivered') DEFAULT 'claimed'` to `claims` table
- Add `deliveryStage?: 'claimed' | 'ordered' | 'delivered'` to `ItemClaim`
- Add `ClaimService.updateDeliveryStage(itemId, stage)` method
- `ItemDetailModal.tsx`: stage stepper for claimers only
- Supabase Database Webhook on `claims` UPDATE: when `delivery_stage = 'delivered'`, push notification to `list_owner_id` with no item details

---

### 6. Expiring Items (Need By Date)
Items can have a "need by" date. Past-due items auto-grey out and move to an "Expired" section so the list stays clean.

- Add `needs_by TIMESTAMPTZ NULL` to `items` table
- Add `needsBy?: string | null` to `GiftItem`
- Update `mapRowToItem()`, `addItem()`, `updateItem()` in `ListService.ts`
- `AddItemScreen.tsx`: date picker using `@react-native-community/datetimepicker`
- `GiftItemRow.tsx`: orange urgency chip when within 3 days; greyed opacity when past
- `ListDetailScreen.tsx`: split FlatList into active and expired sections

---

### 7. List Visibility Windows
Auto-reveal a list on a start date and auto-hide it after an end date. No manual toggling, no forgetting.

- Add `visible_from TIMESTAMPTZ NULL` and `visible_until TIMESTAMPTZ NULL` to `lists` table
- Add to `GiftList` model and `mapRowToList()` in `ListService.ts`
- Update `listenToSharedLists()` / `getList()` queries to filter by current timestamp
- Date pickers in `ListEditScreen.tsx`

---

### 8. Item Tags / Categories
Tag items (Tech, Clothing, Experience, Books, etc.) for filtering and for Gift DNA cross-referencing.

- Add `tags TEXT[] DEFAULT '{}'` to `items` table
- Add `tags?: string[]` to `GiftItem`
- Update `mapRowToItem()`, `addItem()`, `updateItem()`
- `AddItemScreen.tsx`: multi-select tag chip picker (predefined list + custom)
- `ListDetailScreen.tsx`: tag filter bar above FlatList

---

### 9. "Already Own" Flag
Mark items as "I already own this" — they appear on your profile as a collection reference so friends can check before buying something you already have.

- Add `already_own BOOLEAN DEFAULT false` to `items` table
- Add `alreadyOwn?: boolean` to `GiftItem`
- `ListDetailScreen.tsx`: for the owner, show already-owned items in a collapsed "Collection" section at the bottom
- `UserProfileScreen.tsx`: "Collection" tab showing a friend's already-owned items

---

### 10. Private Owner Notes
Notes on items visible only to the list owner — e.g. "Dad mentioned this in October." Never visible to givers.

- Add `owner_note TEXT NULL` to `items` table
- Add `ownerNote?: string` to `GiftItem`
- `AddItemScreen.tsx`: "Private note (only you see this)" field
- `ListDetailScreen.tsx` / `ItemDetailModal.tsx`: render `ownerNote` only when `isOwner === true`

---

### 11. Smart Duplicate Detection
Before saving a new item, warn if a very similar item name or URL already exists on the list. Prevents accidental duplicates.

- `AddItemScreen.tsx`: on `handleAdd()`, before the `ListService.addItem()` call, query existing items and do a case-insensitive name comparison; if `similarity > 0.8` show an Alert with "A similar item exists — add anyway?"
- No new DB fields needed — purely client-side check

---

### 12. Item Condition (New / Used / Refurbished)
For registry-style lists where used items are acceptable, let owners specify the condition they want.

- Add `condition TEXT CHECK IN ('new','used','refurbished') DEFAULT 'new'` to `items` table
- Add `condition?: 'new' | 'used' | 'refurbished'` to `GiftItem`
- `AddItemScreen.tsx`: segmented control picker (default hidden, expand via toggle)
- `GiftItemRow.tsx`: small badge when condition is not 'new'

---

### 13. Smart List Archive
Automatically archive lists 30 days after their `event_date` passes. Keeps the Dashboard clean without manual work.
